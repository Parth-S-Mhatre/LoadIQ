## ⚙️ Setup

### 1. Install dependencies

```bash
cd Backend
pip install fastapi uvicorn lightgbm xgboost scikit-learn numpy pandas joblib firebase-admin
```

Or with a requirements file:

```bash
pip install -r requirements.txt
```

**requirements.txt**
```
fastapi>=0.100.0
uvicorn>=0.23.0
lightgbm>=4.0.0
xgboost>=2.0.0
scikit-learn>=1.3.0
numpy>=1.24.0
pandas>=2.0.0
joblib>=1.3.0
firebase-admin>=6.0.0
python-multipart>=0.0.6
```

### 2. Generate model artifacts (first time only)

The backend requires 6 `.pkl` files generated by the training notebook.

```bash
# Open and run all cells in:
../DATA_preprocessing/energy_model_upgraded.ipynb
```

Files saved to `../DATA_preprocessing/Modelling/`:

```
lgb_load_model.pkl       ← LightGBM primary model
xgb_load_model.pkl       ← XGBoost secondary model
ridge_load_model.pkl     ← Ridge regression baseline
X_scaler.pkl             ← MinMaxScaler (used only for Ridge)
feature_names.pkl        ← Ordered list of all 55 feature names
train_medians.pkl        ← pd.Series of training medians for missing-value fill
```

### 3. Run the servers

```bash
# Terminal 1
python Model1.py     # http://localhost:8001

# Terminal 2
python Model2.py     # http://localhost:8002
```

### 4. Verify startup

```bash
curl http://localhost:8001/health
curl http://localhost:8002/health
```

**Expected response:**
```json
{
  "status": "ok",
  "models_loaded": ["lightgbm", "xgboost", "ridge", "ensemble"],
  "feature_count": 55,
  "default_model": "ensemble"
}
```

## 🔌 API Reference — Model1.py (Port 8001)

**Target:** `DE_LU_load_actual_entsoe_transparency` — Germany + Luxembourg electricity demand (MW)

### POST `/predict`

Predict load for a single time step.

**Minimum request body:**
```json
{
  "hour": 10,
  "day_of_week": 1,
  "month": 1
}
```

**Full request body (best accuracy):**
```json
{
  "hour": 10,
  "day_of_week": 1,
  "month": 1,
  "model": "ensemble",

  "DE_load_forecast_entsoe_transparency": 69000,
  "DE_LU_load_forecast_entsoe_transparency": 68500,
  "DE_LU_price_day_ahead": 95,
  "DE_solar_generation_actual": 4200,
  "DE_wind_generation_actual": 18000,
  "DE_wind_onshore_generation_actual": 12000,
  "DE_wind_offshore_generation_actual": 6000,

  "load_lag_1h": 67800,
  "load_lag_2h": 67500,
  "load_lag_3h": 67200,
  "load_lag_6h": 66800,
  "load_lag_12h": 65000,
  "load_lag_24h": 66500,
  "load_lag_48h": 65800,
  "load_lag_168h": 65900,
  "load_rolling_mean_24h": 66200,
  "load_rolling_std_24h": 1200,
  "load_rolling_mean_168h": 65500,
  "load_rolling_std_168h": 2000
}
```

**Response:**
```json
{
  "predicted_load_mw": 68234.50,
  "model_used": "ensemble",
  "features_supplied": 19,
  "features_total": 55,
  "lag_features_present": true,
  "accuracy_note": "High accuracy — lag features provided.",
  "model_breakdown": {
    "lightgbm": 68100.20,
    "xgboost": 68430.80,
    "ensemble": 68234.50
  }
}
```

**Model options:**

| Value | Description |
|-------|-------------|
| `"ensemble"` | LightGBM 60% + XGBoost 40% — **default, best accuracy** |
| `"lightgbm"` | LightGBM only — fastest, great for complex patterns |
| `"xgboost"` | XGBoost only — strong baseline |
| `"ridge"` | Ridge regression — linear, interpretable |

## 🔌 API Reference — Model2.py (Port 8002)

**Target:** `GB_GBN_load_actual_entsoe_transparency` — Great Britain electricity demand (MW)

### POST `/predict`

Single-step prediction. Accepts same structure as Model1 plus `last_24_hours`.

```json
{
  "hour": 14,
  "day_of_week": 2,
  "month": 6,
  "model": "ensemble",
  "last_24_hours": [27500, 27800, 28100, 28400, 28200, 28000,
                    27900, 27700, 27600, 27500, 27800, 28100,
                    28500, 28900, 29100, 29000, 28800, 28500,
                    28200, 27900, 27600, 27400, 27200, 27000]
}
```

> **Tip:** Providing `last_24_hours` auto-populates all lag features (`load_lag_1h`, `load_lag_24h`, `load_rolling_mean_24h`, etc.) for maximum accuracy.

### POST `/predict_batch`

Multi-step iterative forecast up to 168 steps (1 week) ahead.
Each predicted value automatically feeds into the next step's lag features.

```json
{
  "last_24_hours": [27500, 27800, 28100, 28400, 28200, 28000,
                    27900, 27700, 27600, 27500, 27800, 28100,
                    28500, 28900, 29100, 29000, 28800, 28500,
                    28200, 27900, 27600, 27400, 27200, 27000],
  "horizon": 24,
  "model": "ensemble"
}
```

**Response:**
```json
{
  "horizon": 24,
  "predictions": [
    { "step": 1, "predicted_load_mw": 27850.20, "model_used": "ensemble", "fallback_used": false },
    { "step": 2, "predicted_load_mw": 28120.40, "model_used": "ensemble", "fallback_used": false }
  ],
  "prediction_source": "ensemble",
  "fallback_used": false
}
```

Legacy health check — preserved for frontend compatibility.

## 🛡️ Error Handling & Fallback

Both servers have three layers of protection:

**Layer 1 — Input validation**
Pydantic validators reject invalid `hour` (0–23), `day_of_week` (0–6), `month` (1–12) before the model runs.

**Layer 2 — Median fill**
Any missing feature is filled with the training-set median automatically. The model never receives zeros for missing values.

**Layer 3 — Heuristic fallback (Model2 only)**
If the ML model raises an exception during batch prediction, a weighted heuristic using `recent_mean`, `daily_anchor`, and `momentum` returns a reasonable estimate. The response flags `"fallback_used": true` so the frontend can display a warning.

## 📂 Directory Structure Expected by Backend

```
LOADIQ/
├── Backend/
│   ├── Model1.py
│   └── Model2.py
└── DATA_preprocessing/
    └── Modelling/
        ├── lgb_load_model.pkl
        ├── xgb_load_model.pkl
        ├── ridge_load_model.pkl
        ├── X_scaler.pkl
        ├── feature_names.pkl
        └── train_medians.pkl
```

`Model1.py` resolves `MODEL_DIR` as:
```python
BASE_DIR  = Path(__file__).resolve().parent.parent   # → LOADIQ/
MODEL_DIR = BASE_DIR / "DATA_preprocessing" / "Modelling"
```

If your structure differs, update `MODEL_DIR` in both files.

## 🔒 Security Notes

- CORS is currently set to `allow_origins=["*"]` — restrict to your frontend domain in production.
- Firebase credentials are loaded from environment variable `FIREBASE_SERVICE_ACCOUNT_JSON` or `serviceAccountKey.json`. Never commit `serviceAccountKey.json` to Git.
